# 설계 구조: 강성 평가 스터디 화면 정리 (v0.23.1, UI 전용)

- 상태: 구조 확정(2026-11-17). 상세 계약은 `docs/contracts/esl_doe_ui_tidy.md` 에서 이 문서를 원본으로 쓴다. 충돌하면 이 문서가 우선.
- 범위: `frontend/` 만. 백엔드·API·스키마·결과 파일 변경 없음. 기준 화면 2560×1440.
- 사용자 요구: 강성 스터디 GUI 의 중복 제거, 세로 스크롤 축소. 현재 UI 뼈대(카드 종류·순서·번호, 색·폰트)는 유지.

## 1. 불변 원칙
1. 정보는 지우지 않는다. 옮기거나 합치거나 접는다. 접힌 것은 한 번의 클릭·툴팁으로 볼 수 있다.
2. 새 버튼·새 기능 없음. 기존 버튼은 위치만 묶는다.
3. 카드 순서·번호(①~⑦)와 시나리오별 카드 유무는 그대로.
4. ≤2200px 는 기존처럼 1열로 접힌다(기존 분기점 재사용). 2560 에서만 2열 이득.
5. 새 레이아웃 수단은 2개까지: Card 접기 속성, 결과 2열 그리드. 나머지는 기존 클래스(.doe-grid, .grid2, MsgFold, details, .seg, --tbl-max) 재사용.

## 2. 한 정보 한 자리 (중복 규칙)
| 정보 | 단일 위치 | 없앨 곳 |
|---|---|---|
| 진행(Steps+JobProgress) | 제목줄 아래 진행 띠 1개(현재 돌고 있는 작업 것) | ①·미리보기·결과 카드 안의 같은 쌍 |
| 실패 | JobFailBanner | 카드 안 BlockErr 중 같은 실패를 다시 말하는 것 |
| 스터디 수준 경고 | 결과 카드 "상태 띠"의 경고 칩 + MsgFold(접힘) | 결과 상단 무제한 ul |
| 안(design) 수준 경고 | 순위표 행 배지(썸네일 배지는 다른 뷰라 유지) | 순위표 위 요약 줄들 → 상태 띠 칩으로 |
| 지표 정의·정렬 설명 | 순위표 "ⓘ 지표 정의" details 1개 | 정렬 문구 줄, ESL별 표 설명 줄(→ 같은 details 안으로) |
| 검증 낙하 권고 문구 | 검증 낙하 버튼 툴팁 + VerifyDropCard 머리말 1줄 | 결과 하단 안내문, sm-verify-note/sm-cross-note |
| 요소·노드 수, 시나리오, 경계 경고 수 | ① 입력 요약 | 다른 카드 right 의 반복 |

## 3. 결과 카드 구조 (핵심)
```
[결과 카드 머리: 제목 | 스터디 받기 묶음(결과 받기 zip · 순위 CSV · 파일 ▾)]
[상태 띠 1줄: 기준 재현(지그) · 하중 전달 · 메시 품질 · 1위 경고 여부 · 경고 n ▾]   ← 칩, 상세는 툴팁/펼침
┌ 왼쪽(순위) ──────────────┐ ┌ 오른쪽(선택 안 dNNN) ─────────────┐
│ 순위표 (내부 스크롤)      │ │ 머리: 선택 안 id·변수값 | 선택 안 작업 묶음 │
│ ESL별 개선율 표           │ │   (재낙하 입력 받기[엔트리] · 검증 낙하)     │
│ ⓘ 지표 정의 (접힘)        │ │ 3D 비교                              │
│                          │ │ 민감도                               │
└──────────────────────────┘ └────────────────────────────────────┘
```
- 상태 띠: 지금 순위표 위·아래에 흩어진 5~6줄(JigLine, best-clean 2줄, MESH_QUALITY 띠, LoadTransferDiag 요약, 경고 수)을 칩 한 줄로. 각 칩 = 짧은 값 + 상태색, 상세는 title 또는 클릭 시 띠 아래에 해당 상세 1개만 펼침(LoadTransferDiag details, 경고 MsgFold 재사용). ⚠ 규칙(지그 상쇄 경고 1개 등)은 v0.23.0 계약 그대로.
- 버튼 두 묶음: "스터디 받기"(카드 머리 오른쪽)와 "선택 안 작업"(오른쪽 열 머리). 파일 링크 여러 개는 `파일 ▾` details 안으로. 검증 낙하 버튼은 한 곳만.
- 민감도·3D 가 없는 시나리오(compare 등): 오른쪽 열에 있는 것만 쌓고, 둘 다 없으면 왼쪽 열을 전폭으로.
- 높이 예산(2560×1440, 결과 단계): 제목줄+진행 띠+접힌 설정 요약 ≤ 200px, 결과 카드 ≤ 화면 나머지. 왼쪽 = 순위표가 남는 높이를 채우고(--tbl-max 재정의) ESL별 표는 고정 상한, 오른쪽 = 3D 비교 + 민감도가 같은 높이 안. 목표: 결과 단계에서 페이지 세로 스크롤 없이 결과 카드 전체가 보임(VerifyDropCard 는 그 아래).

## 4. 단계 초점 (자동 접기)
- 화면은 지금 단계의 카드만 펼친다. 단계 = 설정(미리보기 전) / 미리보기 / 결과.
- 지난 단계 카드는 한 줄 요약 막대로 접힌다(카드 제목 + 기존 right 요약 + 펼치기). 예: 결과 단계에서 ① 입력·②~⑤ 비드/변수/평면도·미리보기는 각각 한 줄.
- 사용자가 펼치면 그 상태를 세션 동안 기억(MsgFold 의 storeKey 방식). 실행 중·실패한 단계의 카드는 접지 않는다.
- 구현 수단: `Card` 에 선택 속성(접힘 가능, 기본 접힘 여부, storeKey). 속성을 안 주면 기존과 동일(다른 화면 영향 없음).

## 5. 긴 글
- 항상 펼쳐진 안내문(결과 하단, 새 스터디 하단 시나리오 설명, DoeInputs 도움말 중 2문장 이상)은 `ⓘ` details 로 접거나 툴팁으로. 한 줄짜리 핵심 안내는 유지.

## 6. 새 스터디 화면
- ① 입력 단일 카드 안을 2560 에서 2열: 왼쪽 = ESL 선택·업로드, 오른쪽 = 형상표·고급. 72rem 폭 제한은 열 안에서만. ≤2200px 는 1열.

## 7. 목록 화면
- 손대지 않는다. 단, 파일 머리 주석의 "최적 개선율 열" 불일치만 주석을 실제에 맞게 고친다.
