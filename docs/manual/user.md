# ESL(등가정적하중) 사용 가이드

화면 상단 바의 **사용 가이드**와 같은 내용이다(화면은 카드마다 해당 화면 바로가기가 있다). 화면 내용은 `frontend/src/pages/guide/content.ts`, 이 문서와 카드 제목이 같아야 한다(시험이 대조).

전체 흐름: **rad + h3d 올리기 → ① 추출 → ② t* → ③ 지지점 → ④ ESL → ⑤ 검증 → ⑥ 내보내기 → 라이브러리**
결과는 모두 Case 폴더 하나에 단계별로 쌓인다. 앞 단계를 바꾸면 뒤 단계를 다시 실행한다.

---

## 시작하기

### Case란
낙하 씬 1개를 분석하는 단위. **Case 1개 = h3d 1개 + rad(include 포함) + 대상 파트 1개.**
- ①~⑥ 단계의 결과가 Case 폴더 하나(`01_extract` … `06_export`, 보고서)에 차례로 쌓인다.
- 앞 단계를 바꾸면 뒤 단계에 "이전 단계가 바뀌었습니다"가 뜬다 — 그 단계부터 다시 실행.
- 같은 제품의 여러 씬은 Case를 여러 개 만들고, 검증된 결과를 라이브러리에 모아 함께 본다.

### 새 Case — 내 PC에서 올리기
기본 방법. rad·include와 h3d를 브라우저로 서버에 올리면 **서버가 h3d에서 필요한 값을 직접 추출**한다(서버 HyperView, h3d는 읽기만).
1. Case 목록 → **새 Case** → "내 PC에서 올리기" 탭.
2. ① rad·include: `_0000.rad`과 include 파일을 고르거나 폴더째 끌어다 놓는다.
3. ② h3d 결과 파일 1개(수 GB~수십 GB). **올리기**를 누르면 속도와 남은 시간이 보인다(64 MB 조각을 여러 개 동시에 보낸다).
4. 목록 왼쪽 체크박스로 파일을 고르고 **지우기(n)**를 누르면 선택한 파일만 목록에서 빠진다(선택이 없으면 비활성 + 사유, 전체 선택 후 지우면 업로드 취소). 전송 중인 파일은 **멈춤** 뒤에 고를 수 있다. 올리기·확인을 마친 뒤 지우면 서버가 자동으로 다시 확인(재검사)한다.
5. 끊기거나 탭을 닫았으면 같은 파일을 다시 고르고 **올리기**(이어 올리기) — 서버가 받은 조각은 다시 보내지 않는다(파일 이름·크기·수정 시각으로 같은 업로드를 찾음).
6. 확인 결과에 include가 빠졌다고 나오면 **추가로 올리기**로 그 파일만 더 올린다.
7. Case 이름(영문·숫자·_·-, 결과 폴더 이름)·대상 파트(기본 `chassis_rear`) 확인 → **Case 만들기**.

> 팁: h3d가 5 GB를 넘으면 화면이 PC 도구의 **압축 모드**를 권한다 — 대상 파트와 필요한 결과만 남긴 h3d(보통 원본의 수 %)를 PC에서 만들어 올리는 방법이다. 아래 "PC에서 추출해 올리기(PC 연결)". 참고 시간: 30 GB ≈ 1 Gbps 약 5분, 100 Mbps 약 45분(동시 전송 기준 하한).

전송 방식: 파일을 64 MB 청크로 잘라 서버가 허용하는 만큼(최대 4개) 동시에, 청크 번호 순서로 보낸다(File.slice — 파일 전체를 메모리에 올리지 않고 최대 약 320 MB). 청크마다 sha256을 함께 보내 손상되면 그 청크만 다시 보낸다. 일시 오류는 자동 재시도, 서버가 동시 한도(429)를 알리면 잠시 기다렸다 다시 보낸다. 속도는 최근 10초 이동 평균이고 남은 시간은 그 속도로 계산한다. 서버가 구버전이면 예전처럼 하나씩 순서대로 보낸다.

**다른 페이지로 가도 계속**: 올리기를 시작하면 주소가 `…/cases/new?upload=<id>`로 바뀌고, 같은 탭에서 다른 화면으로 갔다 와도 전송은 계속된다. 상단 바 **업로드 37%**(여러 개면 "업로드 2건 · 45%")를 누르면 그 업로드 화면으로 돌아오고, 끝나면 잠깐 "업로드 완료 — 열기"가 보인다. 전송 중에 탭을 닫거나 새로고침하면 브라우저가 경고하며, 끊겨도 같은 파일을 다시 고르면 이어 올린다.

**진행 중인 업로드**: 업로드 세션은 계산 대기열과 별개로 사용자당 최대 2개까지 열려 있을 수 있다. "내 PC에서 올리기" 아래 **진행 중인 업로드** 목록(없으면 숨김)에서 이름·파일 수·받은 양·상태를 보고 **이어서 열기**로 마무리하거나 **취소**한다(취소해도 파일은 삭제되지 않고 서버 `_backup`으로 옮겨진다). "진행 중인 업로드가 2개입니다" 오류가 나면 이 목록이 저절로 펼쳐진다.

### 새 Case — 서버 폴더에서 고르기
이미 서버 업로드 폴더에 있는 rad·h3d(또는 추출 결과 폴더)를 다시 쓸 때.
1. "서버 폴더에서 고르기" 탭에서 폴더 이름을 눌러 들어간다.
2. rad 파일 옆 **rad 선택**, h3d 파일 옆 **h3d 선택**(또는 `done.json`이 있는 폴더 옆 **결과 폴더 선택**) 배지를 누른다.
3. rad 확인 표에서 대상 파트가 있는지 보고 **Case 만들기**.
4. 경로를 직접 붙여 넣어야 할 때만 "고급: 경로 직접 입력"을 펼친다.

> 내 PC의 경로(예 `F:\Hyper_work`)는 서버에서 보이지 않는다. 서버 폴더 탭에는 서버에 올라온 파일만 보인다.

### PC에서 추출해 올리기(PC 연결)
h3d가 아주 크거나 망이 느릴 때. 기본은 **압축 모드** — 대상 파트와 변위·최대 변형률(Mid)·소성 변형률(Mid)의 전 프레임만 남긴 h3d를 PC에서 만들어(보통 원본의 수 %) rad·include와 함께 서버로 자동으로 올린다. 원본 h3d는 PC에 그대로 남는다. 끝나면 새 Case 화면이 채워진 채로 열린다.
1. 처음 한 번: 저장소 클론 폴더 맨 위의 `update.bat`을 더블클릭해 PC 도구(`ESL_extract.bat`)를 설치·갱신한다(서버용 `deploy\update.bat`과 다른 파일).
2. 새 Case → **"PC에서 추출해 올리기"** 탭 → **PC 연결 코드 만들기**(실행(power) 이상). 6자리 코드가 남은 시간과 함께 15분 동안 보인다(1회용, 지금 프로젝트에만 올릴 수 있음).
3. h3d와 rad 파일을 함께 `ESL_extract.bat` 위로 끌어다 놓는다(h3d만 놓으면 rad 고르는 창). 처음 한 번은 서버 주소(탭에 표시, 예 `http://<대시보드 주소>/esl`)와 연결 코드를 묻는다 — 연결 정보는 PC에 암호화(DPAPI)해 저장하고 30일 유지된다.
4. 실행 창에서 모드를 묻는다(10초 안에 **Enter = 압축**, **O = 원본** h3d 그대로, **P = 기존 PC 추출** — HyperView로 CSV 추출). 다른 파트나 다른 결과로 다시 해석할 계획이면 **O(원본)**를 고른다. 새 Case 화면의 **압축 모드(권장)** 체크는 이 브라우저의 안내 기본값(기본 ON)일 뿐 PC 도구에는 전달되지 않는다 — 해제하면 화면 안내가 "O를 누르세요 / `/original`"로 바뀐다.
5. 압축(또는 PC 추출) → rad의 include 수집(누락 시 경고) → 업로드(청크 병렬·이어 올리기)가 끝나면 브라우저가 새 Case를 채운 채로 연다 → **Case 만들기**. 압축 모드로 올린 Case는 ① 입력에 **압축 모드** 배지(원본 → 줄인 크기, hvtrans 시간, 파트)가 보인다.
- 판단 기준: 콘솔에 include 누락 경고가 없는지 · "연결된 PC" 목록에 내 PC가 "사용 중"으로 보이는지.
- **연결된 PC**: 같은 탭 아래 목록(장치명·상태·마지막 사용·만료). PC를 잃어버렸거나 더 쓰지 않으면 **폐기** — 그 PC의 도구는 다음에 코드를 다시 묻는다.
- 업로드만 다시: `ESL_upload.bat <결과 폴더>`(추출 생략). 끊기면 다시 실행하면 이어 올린다. 다른 파트를 뽑으려면 명령창에서 `ESL_extract.bat <h3d> <파트 이름|ID>`.

## ①~⑥ 단계

### ① 입력·추출
h3d에서 대상 파트의 메시·변위·변형률 이력을 읽어 Case 폴더(`01_extract`)에 정리한다. h3d는 읽기만 한다.
- Case를 열면 ① 입력. rad·h3d 경로와 파트 확인 표를 본다. **추출 실행** → h3d로 만든 Case는 먼저 **"서버에서 추출 중(HyperView)"** 단계가 진행·로그와 함께 보이고(수 분~수십 분), 이어서 정리·t* 후보 계산을 한다.
- 오른쪽 "계산 대기열"에 동시 실행 수(예 1/2, 설정 `worker.slots`)가 보인다 — 다른 Case 계산과 동시에 돌 수 있다(같은 Case는 차례대로).
- 판단 기준: 파트 요소 수가 예상과 같은지(예 chassis_rear 약 22만) · 프레임 수·후보 프레임이 채워졌는지 · 경고(include 누락, 파트 없음)가 없는지.
- **누적 낙하 씬(2차 이후 낙하)**: rad 가 이전 낙하 해석의 상태 파일(`.str` 변형 형상·두께, `.sta` 초기 소성 변형률)을 `#include` 하면 Case 위에 **누적 씬** 배지가 붙고 ① 아래에 **누적 입력** 카드(상태 파일·좌표 출처·두께 변화 t/t₀·이전 소성·h3d 판정)가 보인다. 계산 형상(K_L)은 이전 런 변형 좌표·변형 두께, ② t* 는 누적(이전 + 이번) 순위·이번 낙하 증분의 첫 도달 시점, ⑤ 변형률 참고 비교는 이번 낙하 증분 기준. 새 Case 업로드 때 `.sta`·`.str` 를 rad 와 함께 올린다(빠지면 "이전 런 상태" 표시). 누적 씬은 **서버 추출(h3d 업로드)** 을 권한다 — PC 추출본에는 이전 소성 기준 후보·frame 0 값이 없어 일부 판정이 근사가 된다.

### ② t* (하중 시점)
정적 하중으로 바꿀 순간 t*를 고른다. h3d의 Max_Strain·Plastic Strain은 요소별 누적 최대(max-hold)라, **t* = 최종 최대값에 처음 도달한 프레임(first-reach)**.
- 기본 지표 Max_Strain의 1순위 후보가 자동 선택된다. 이력 곡선·후보 표(요소·값·시각)를 보고 필요하면 다른 후보를 골라 **t* 확정**.
- 판단 기준: 곡선이 t* 이후 평평한지 · 1순위 요소가 실제 관심 부위(파손·고변형 위치)인지 · Plastic Strain 결과도 비슷한 시점인지.

### ③ 지지점 (3-2-1)
파트를 자유물체로 보고 강체 운동 6자유도만 막는 **3-2-1 정정 구속점** 3개를 정한다. 하중이 자기평형이라 반력은 거의 0.
- PCA 평면 산점도의 자동 추천 노드 3개를 그대로 두거나 노드 ID를 바꾼 뒤 **지지점 저장**.
- 판단 기준: 세 노드가 넓게 퍼지고 한 줄에 놓이지 않았는지 · 고변형 부위(핫스팟)에서 떨어져 있는지 · 파트 밖 노드가 아닌지(`NODE_NOT_IN_PART`).

### ④ ESL 계산
t* 변위에서 강체 운동을 빼고(u_rel) 절점 등가하중 **F_eq**를 계산한다.
- **ESL 계산** → 강체 회전각, ΣF·ΣM·평형 오차, 잡음 지표, F_eq 상위 노드 표.
- 판단 기준:
  - 평형 오차 |ΣF|/Σ|F| ≤ 1e-6(자기평형)
  - 강체 제거 품질 OK(WARN이면 변형이 아주 큰지 확인)
  - 잡음 경고 없음 — h3d 변위가 float32라 변형이 작으면 F_eq가 잡음에 묻힌다(검증에서 `NOISE_FLOOR` FAIL)
  - F_eq 상위 노드가 충돌·접촉 부위와 맞는지
- **3D 하중 보기**(v0.5.8): 결과 아래에 부품 3D 모델이 열린다. 표면 색은 **면압 |Fn|/A [MPa]**(Blues, 레전드 숫자로 범위 수정), 화살표 단계 슬라이더는 왼쪽 끝 100 노드 → 50 → 20 → 10 노드 → **군집 합력 5·4·3·2**(합력은 ΣF≈0 자기평형). 표 행을 누르면 3D에서 해당 화살표·노드가 강조되고(더블클릭 = 카메라 이동), 3D에서 화살표를 눌러도 표 행이 선택된다. **변형 형상**은 u_rel×배율(표시 전용, **실제 크기(×1)** 로 끔), **맞춤**은 카메라를 부품 전체에 맞춘다. **원근**(v0.7.1) 체크 = 원근, 해제 = 직교(기본·치수 왜곡 없음) — 같은 시점·같은 크기로 바뀌고 이 브라우저에 기억된다. 3D를 못 쓰는 브라우저·큰 부품(413)이면 사유 한 줄과 상위 100행 표만 보인다.
- **실행 상태 서랍**: 상단 바의 칩 2개(계산 대기열 · 워커)를 누르면 오른쪽에 서랍이 열린다(작업 화면을 가리지 않는 비모달, Esc·✕로 닫음). 열림/닫힘은 브라우저에 기억되어 새로고침해도 유지된다.

### ⑤ 검증
F_eq를 정적 해석으로 다시 풀어 ESL이 원래 낙하 해석의 **변위**를 얼마나 재현하는지 본다(v0.5.7: 변위가 주 판정, 변형률은 참고).
- **검증 실행** → **판정 카드**(PASS / FAIL / 판정 불가 / 이전 판정 체계) + 4지표 + 변위 비교 + 단면선 + 변형률(참고). 끝나면 Case 보고서(HTML)가 자동으로 만들어진다 — **보고서 보기**.
- 판정 4지표(값 아래에 기준이 함께 나온다. 기준은 설정으로 바꾼다):
  - 변위 RMS(상대) ≤ `disp_rms_rel_max`, 변위 최대 오차(상대) ≤ `disp_max_rel_max` — 상대 = 오차 e ÷ U(Radioss 최대 변위, 미소 강체 제거 후)
  - 반력(상대) ≤ `reaction_rel_max`, 잡음 바닥 ≤ 기준 — 넘으면 FAIL
- **변위 비교(전 노드)**: 레이어(오차 e/U · Radioss u_rel · ESL u_val) 컨투어, 로그 히스토그램(점선 = 판정 기준), 오차 상위 노드 표(지지 노드는 "지지" 표시).
- **컨투어 색 범위**: 기본은 서버가 준 견고한 자동 범위(P99). 레전드의 숫자 칸에 직접 입력하면 수동 범위가 되고(범위 밖은 끝색 + ▲/▼ 개수), **자동**을 누르면 되돌아간다.
- **단면선**: 축(길이 방향 · 폭 방향) 선택, 추천(최대 변위 오차 노드 · 변형률 hotspot 1위 지나는 단면), 위치 슬라이더(0~1). **지도를 눌러도** 단면 위치가 옮겨진다. 위치 0~1은 서버가 알려준 요소 중심 범위(`xi_range`·`eta_range`) 기준이다. 변형은 확대해서 그리며(배율 표기), **실제 크기(×1)** 로 끌 수 있다.
- 변형률(참고, 판정 아님): 기준 초과 요소 수·소성 영역 요소·|오차| 분위수·겹쳐보기. 같은 단면 위치선이 겹쳐보기에도 표시된다.
- **판정 불가**: 전체 재해석이 없거나 변형이 없어 변위를 비교할 수 없는 경우. **이전 판정 체계**: 0.5.7 이전 검증(당시 판정 표시) — 다시 검증하면 변위 분석이 나온다.
- FAIL·판정 불가이면 ② t* 후보나 ③ 지지점을 바꿔 다시 계산해 본다. FAIL 결과도 사유를 적어 라이브러리에 "확정" 등록할 수 있다.

### ⑥ 내보내기 · 결과 받기
F_eq와 3-2-1 구속을 해석 입력 파일로 쓴다: Radioss inc(`/CLOAD`·`/BCS`), OptiStruct fem, CSV.
- 대상을 고르고 **내보내기** → `06_export` 아래 파일이 생긴다.
- **결과 받기(zip)**: 내보내기 파일·보고서·요약 json·csv를 한 번에 내 PC로 받는다(Case 상단 메뉴에도 있음). 대용량 원자료(npz)는 빠진다.
- zip이 너무 크면(기본 5 GB 초과) 폴더 경로가 표시된다 — **경로 복사** 후 탐색기에서 연다.

### 실행 이력 · 지난 결과 다시 보기
지난 작업의 입력값·오류·소요 시간·로그를 다시 보고, 그때의 결과를 읽기 전용으로 연다.
- **Case 상단 메뉴 → 실행 이력**: 그 Case의 작업을 시간순으로(상태 필터: 전체/성공/실패·중단). **프로젝트 상단 → 실행 이력**: 프로젝트 전체 작업을 작업 종류·상태·기간·검색(Case 제목·폴더·작업 id)·'내 작업만'으로 좁힌다. 필터는 주소에 남는다.
- 행을 누르면 **작업 상세**: 개요, 입력값, 오류(실패 시 맨 위; 취소된 작업은 경고만), step별 소요, 로그, 결과. 결과가 있으면 주 버튼 **그때 결과 열기**. 대기 시간은 아직 시작 전이면 `–`로 나온다. 로그가 길면 **이어서 보기**로 이어 읽는다. step의 실행 명령(command)은 전역 관리자에게만 보인다.
- 한 번에 최대 200건까지 읽는다(화면은 30건씩 **더 보기**).
- ④·⑤는 **과거 실행 · 시각** 배지가 붙은 읽기 전용 화면으로 열린다(①·⑥·보고서는 작업 상세의 결과 카드에서 보고, 라이브러리 작업은 **현재 분석·비교 열기**로 간다). 이후 입력이 바뀌었으면 **입력 바뀜** 칩(사유는 마우스를 올리면)과 **현재와 다른 점** 표가 나오고, 실행·등록 버튼은 없다. **현재 결과로**를 누르면 최신 화면으로 돌아간다.
- 파일이 필요한 보기(하중표·전 요소 비교·내보내기 파일·보고서)는 파일이 보존된 실행만 열린다. 아니면 "파일 보존 안 됨 — 기록된 값만 표시"가 나오고 기록된 값만 보인다.

### 비드 최적화(서버 실행)
라이브러리에서 고른 ESL로 서버가 OptiStruct 비드(DTPG) 최적화를 직접 돌린다(v0.7.0). 사용자 PC에서 덱을 돌릴 필요가 없다. 결과는 라이브러리에 넣지 않고 라이브러리 **최적화 실행** 탭과 실행 이력에 남는다.

| | S1 기존 형상 | S2 템플릿 |
|---|---|---|
| 대상 메시 | 기준 ESL(첫 행)의 Case 입력 rad 대상 파트(서버가 제자리에서 읽기만) | 등록한 평판 템플릿(.rad/.fem) |
| 넣을 수 있는 ESL | **같은 모델**(노드 ID + 요소 연결 같음, 목록 ⓜ 표시) | **같은 크기**(같은 인치 + 치수 ±2 %, 템플릿과 ±5 %) |
| 하중 | 노드에 그대로 | 24×14 셀 합력·합모멘트로 옮김 |
| 결과 메시 | 제품 대상 파트를 바꿔 끼울 비드 반영 메시 | 템플릿 형상의 비드 반영 메시 |

**공통 준비 — ESL 고르기**
- 라이브러리 → **항목** 탭에서 ESL 행을 체크한다. 첫 체크가 기준이고, 크기가 다른 행은 체크할 수 없다(툴팁에 이유).
- '모드' 열(덴팅·뒤틀림·굽힘)은 자동 분류(회색)이다. 틀리면 행에서 바로 고친다(굵게 표시, '자동으로'로 되돌림). 모드는 표시·검색과 전략 B 에만 쓰인다.
- **선택한 ESL로 비드 최적화 (n)** → 새 비드 최적화 화면. 모두 같은 모델이면 '기존 형상(S1)' 탭, 아니면 '템플릿(S2)' 탭으로 열린다.

**S1 기존 형상 최적화**
1. ① 대상: 기준 Case·대상 파트·노드/요소·3-2-1(기준 ESL과 같음, 표시만)을 확인하고 PID 표에서 설계 영역 PID를 체크한다(체크 해제 = 비설계).
2. ③ ESL: '다른 모델 ✗' 행이 있으면 **다른 모델 빼기**(또는 같은 크기면 템플릿 최적화로).
3. ② 비드 금지 영역: 이 모델에 저장된 세트가 있으면 자동으로 불러온다. 자동 영역(구멍 주변·가장자리, 회색 빗금)을 켜고 끄고, **＋사각형**으로 사각형을 넣는다(기준 모서리 + X·Y 거리 + 가로·세로 mm). 평면도에서 사각형을 끌거나 방향키(Shift = 10 mm)로 옮기면 숫자가 따라 바뀐다. 다음에도 쓰려면 **이 모델에 저장** — 저장하지 않아도 이번 실행에는 화면 값이 들어간다.
4. ④ 하중 선정 전략: 기본 **A 전부 넣기**(추천). B 모드별 최악(최대 3개), C 군집 대표 k개. **목표 기준**: 기본 절대(추천), 상대는 하중마다 같은 비율 개선. ⓘ 에 방법·출처.
5. ⑤ 비드 치수(경사 45°·폭 60 mm·높이 10 mm 기본)·제목 → **최적화 실행**. 버튼이 회색이면 툴팁에 이유가 있다.

**S2 템플릿 최적화**
1. (최초 1회) 라이브러리 → **템플릿** 탭 → **템플릿 등록** → 쉘 메시(.rad + include 또는 .fem)를 끌어다 놓기 → 업로드·자동 검사(오류 0 이어야 등록) → 제목·인치(선택)·설명 → **등록**.
2. 같은 크기 ESL을 체크 → **선택한 ESL로 비드 최적화** → '템플릿(S2)' 탭.
3. ① 템플릿: 크기가 맞는 템플릿만 고를 수 있다(안 맞으면 이유 표시). PID 표에서 설계 영역 체크. 3-2-1은 서버가 템플릿에서 자동으로 고른다.
4. ② 금지 영역(세트는 **이 템플릿에 저장**) → ④ 전략·목표 기준 → ⑤ 비드 치수 → **최적화 실행**.

**진행·결과 보기**
- 상세 화면: 진행 6단계(대상 준비·하중·선정·덱 생성·OptiStruct·후처리·등록), 로그·취소. OptiStruct 단계는 반복 수로 진행률이 오른다. 라이선스가 모자라면 300 초 간격으로 3번 자동 재시도한다.
- '하중·선정'이 끝나면 하중 선정 표(상태·병합 대상·반대 방향·군집·C⁰·최대 변위·모드)가 먼저 보인다.
- 완료 후: 목적값 수렴 그래프, 비드 맵, 케이스별 C⁰ → C(비율), 비드 면적·최대 높이, **보고서 보기**, 받기(.rad/.fem 비드 반영 메시, zip = 보고서·결과·덱).
- 실패하면 오류 코드·메시지를 확인하고 **다시 시도**(power 이상). 재시도는 실행 당시 설정(금지 영역·전략)을 그대로 쓰며, 덱이 같으면 OptiStruct 해석을 다시 하지 않는다. 설정을 바꾸려면 새 실행을 만든다.
- 다음 단계: 비드 반영 메시로 낙하 해석 → 새 Case → 라이브러리 등록 → 버전 비교로 개선 확인.

### 템플릿 등록(S2)
- 등록 순서는 위 'S2 템플릿 최적화' 1번. 검사 경고(셀당 노드 부족·평탄도 등)는 등록을 막지 않지만 결과 품질에 영향을 준다.
- 템플릿은 모든 사용자에게 공개된다. 삭제는 등록자·관리자만 할 수 있고, 이전 실행이 참조 중이면 삭제 대신 보관(목록에서 숨김, '보관 포함'으로 보기)된다.
- 보관된 템플릿으로는 새 실행을 만들 수 없다(이전 실행의 재시도는 된다).

### 비드 형상 DOE
낙하 하중(ESL)을 고려해 Ch/R 비드 깊이·폭·위치를 바꾼 여러 안의 선형 강성을 비교한다(v0.9.0). 형상은 중립면 STEP 에서 형상 엔진(paicad)이 비드를 인식해 만든다.
1. 라이브러리 항목에서 ESL 을 체크 → **선택한 ESL로 비드 DOE (n)**.
2. 시나리오는 자동 판별(바꿀 수 있음): ① 같은 모델(ESL 원 모델 메시를 모핑) · ② 다른 모델 + B 메시(rad/inc) · ③ 다른 모델 STEP 만(안마다 새 메시, 쉘 물성 t·E·ν 기본값을 확인).
3. STEP(②는 B 메시도)을 끌어다 놓으면 입력 검사가 자동으로 돈다 → **입력 준비**.
4. 비드·변수 표에서 포함 변수·범위(기본 = feasible 추정)·DOE 방식(LHS·Halton·풀 팩토리얼)·안 수·시드를 정하고 **미리보기** → 썸네일 격자에서 충돌·고정 침범 안(회색)을 확인. 미리보기가 끝나야 **DOE 실행**이 켜진다(설정을 바꾸면 다시 미리보기).
5. 결과: 순위표(score·개선율·최대 변위·변형률·스킵/실패 배지), 민감도(SRC·Spearman), 3D 비교(베이스라인 | 선택 안, 같은 색 범위), 최적 안 받기(include/메시·BREP/STEP)·보고서.
- ②③ 평면도의 빨강 점선 = A 체결점·하중 집중부가 B 체결 후보에서 멀다는 경고(차단 아님).
- 선형 강성 상대 비교이므로 최적 안은 검증 낙하 1회로 확인한다. 재실행은 **복제**로 새 연구를 만든다.

## 자주 묻는 질문

**회사 PC에서 '대시보드 계정이 활성 상태가 아닙니다'가 떠요**
회사 프록시가 서버 내부 호출을 가로채던 문제로 v0.4.0에서 고쳤다. 계속되면 브라우저 프록시 예외에 서버 주소를 넣고, 관리자에게 서버 로그의 403 사유를 확인해 달라고 한다.

**'새 Case'·주 버튼이 회색이에요**
프로젝트 역할이 "조회(general)"이면 실행할 수 없다. 버튼에 마우스를 올리면 사유가 보인다. 대시보드 관리자에게 "실행(power)" 역할을 요청한다.

**업로드가 끊겼어요 / 탭을 닫았어요**
같은 파일을 다시 고르고 **올리기**를 누르면 서버가 받은 데부터 이어 올린다(파일 이름·크기·수정 시각이 같아야 함). 청크마다 sha256을 확인하므로 손상된 부분은 다시 보낸다.

**수십 GB 짜리 h3d는 어떻게 올리나요?**
브라우저 올리기는 64 MB 조각을 동시에 여러 개 보내 예전보다 빠르지만, 20~50 GB는 PC 도구의 압축 모드가 가장 빠르다(대상 파트와 변위·최대 변형률(Mid)·소성 변형률(Mid) 전 프레임만 남겨 보통 원본의 수 %). 5 GB를 넘는 h3d를 고르면 화면이 권장 안내를 띄운다. 다른 파트나 다른 결과로 다시 해석할 계획이면 원본이 필요하니 압축을 끄고(실행 창에서 O) 올린다. 원본 h3d는 PC에 남는다.

**올리기 목록에서 파일을 빼고 싶어요 / 잘못 올렸어요**
목록 왼쪽 체크박스로 고르고 **지우기(n)**를 누르면 선택한 파일만 빠진다(선택이 없으면 버튼이 비활성이고 사유가 보인다). 전송 중인 파일은 선택할 수 없으니 **멈춤** 뒤에 고른다. 전체를 선택해 지우면 업로드 자체를 취소한다. 올리기·확인을 마친 뒤 지우면 서버가 자동으로 다시 확인(재검사)한다. 서버에서는 파일을 삭제하지 않고 `_backup` 폴더로 옮긴다. 이미 그 업로드로 Case를 만들었으면 뺄 수 없다.

**'진행 중인 업로드가 2개입니다(사용자당 최대 2개)'가 떠요**
업로드 세션은 계산 대기열(작업 0/2)과 별개로 사용자당 최대 2개까지 열려 있을 수 있다. 새 Case → "내 PC에서 올리기" 아래 **진행 중인 업로드** 목록에서 **이어서 열기**로 마무리하거나 **취소**한다. 취소해도 파일은 삭제되지 않고 서버 `_backup` 폴더로 옮겨진다.

**용량 한도가 얼마예요? '저장 공간 부족'이 떠요**
기본 파일당 64 GB, 업로드당 100 GB. 서버 여유 공간이 모자라면 시작 전에 "저장 공간 부족(507)"으로 막는다 — 관리자에게 알리거나 PC에서 추출한 결과 폴더(수백 MB)만 올린다.

**PC 도구가 '연결 코드가 맞지 않거나 만료' / '잠겼습니다'라고 해요**
코드는 15분 동안 한 번만 쓸 수 있다. 새 Case → "PC에서 추출해 올리기"에서 새 코드를 만들어 입력한다. 잘못된 코드를 여러 번 넣으면 15분 동안 잠긴다(PC별 5회, 서버가 PC를 구분할 수 없는 설치면 서버 전체 30회).

**결과 받기(zip)가 안 되고 경로만 보여요**
zip이 한도(기본 5 GB)를 넘었다. 경로를 복사해 탐색기로 연다. 대용량 원자료(npz)는 기본으로 zip에서 빠진다.

**환경 점검에 CHOLMOD SKIP이 보여요**
정상이다. CHOLMOD(scikit-sparse)는 Windows용 설치 파일이 없어 건너뛰고, Windows 서버는 PARDISO(MKL) 솔버를 쓴다. 솔버 이름은 오른쪽 "워커" 패널에 보인다.

**단계에 '이전 단계가 바뀌었습니다'가 떠요**
앞 단계(t*·지지점 등)를 바꿔 지금 결과가 옛 입력 기준이다. 그 단계의 주 버튼으로 다시 실행한다.

**보고서 버튼이 비활성이에요**
Case 보고서는 ⑤ 검증이 끝나면 자동으로 만들어진다. 검증을 먼저 실행한다.

**새 버전이 나왔는지 어떻게 알아요?**
상단 바 버전(v0.4.0) 옆에 점이 보이면 마지막으로 본 뒤 업데이트가 있었다는 뜻이다. 누르면 업데이트 내역이 열린다.
